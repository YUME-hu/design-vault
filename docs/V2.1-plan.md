## 1. 收藏夹扫描

### 1.1 数据来源与接口

B 站收藏夹走网页端接口，带登录 Cookie（复用 `getBiliCookie()`）：

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 收藏夹列表 | `GET /x/v3/fav/folder/created/list-all?up_mid={uid}` | 需要 `DedeUserID`；返回 id / 标题 / 视频数 |
| 收藏夹内容 | `GET /x/v3/fav/resource/list?media_id={id}&pn={page}&ps=20&platform=web` | 分页；返回 bvid、标题、封面、UP、pubtime、简介摘要 |
| 当前 uid | 优先加密会话里的 `uid`，缺失时调 `/x/web-interface/nav` | 扫码登录时已存 uid，一般不用再查 |

约束：

- 每页 20 条，接口有 `has_more`；
- 请求间保持 1–3s 随机延迟（复用现有 `biliGap()` 思路）；
- 401/-101 → 清会话并提示重新扫码（V2.0 已有链路）；
- 不做自动轮询，全部由用户点按触发。

### 1.2 代码落点

```
packages/core/src/favorites.ts        纯函数：folder/video payload → 归一化模型
packages/adapters/src/ingest/favorites.ts
  getFavFolders()
  getFavVideos(mediaId, page)          ← 网络 + 延迟 + 错误归一
apps/web/app/api/favorites/route.ts               GET  folders
apps/web/app/api/favorites/[mediaId]/route.ts     GET  videos?page=
apps/web/app/api/favorites/extract/route.ts       POST 批量提取（job）
```

批量提取**不新写链路**：复用 `startSearchExtract(video)`，一次一个、串行排队，前端轮询总进度；每个视频的提取结果仍走 M2 的 pending 与查重逻辑。

### 1.3 增量扫描与状态

`data/ingest-state.json` 增加：

```jsonc
{
  "favorites": {
    "123456": {
      "title": "设计灵感",
      "lastScannedAt": "2026-11-05T10:00:00.000Z",
      "lastVideoPubtime": 1730000000,
      "lastPage": 3
    }
  }
}
```

- 收藏夹内容按「最新在前」返回；扫描时从第 1 页开始，遇到 `pubtime <= lastVideoPubtime` 即停（新增内容都在前面）；
- `lastPage` 用于上次中断后的续扫（可跳过前 N 页）；
- 已抓过的视频靠两层兜底：**pending 的 `video + name` 去重** + **本收藏夹游标**；
- `force=true` 时忽略游标，全量重扫（用户手动勾选「重新扫描」）。

### 1.4 批量提取的边界

- 单次最多 **20 个**（一个分页），超出需分批；避免一次触发几十次 DeepSeek；
- 并发固定为 **1**，每个之间 1–3s 延迟；
- 提取前先做本地过滤：`bvid` 已在 pending / 已在 styles 的直接标记「已入库」，不进队列；
- 前端逐条显示状态：排队中 / 读简介 / 分析 / 已写入 / 跳过 / 失败；
- 任务状态放内存 job 表（与现有 extract 一致），页面刷新后丢失可接受（pending 已落盘）。

### 1.5 UI：`/search` 两个 Tab

```
[ 关键词搜索 ] [ 我的收藏夹 ]

我的收藏夹：
  收藏夹下拉（加载中 / 空 / 未登录提示）
  工具栏：全选 · 已选 N 条 · [批量提取] · [重新扫描]
  视频列表（封面 / 标题 / UP / 时长 / 勾选 / 单条提取）
  底部：上次扫描时间 · 本页 N 条 · 增量跳过 M 条
```

未登录时 Tab 2 显示「去 /settings 扫码登录」；接口返回 401 时同样提示。

## 2. 设置面板（V2.1）

### 2.1 DeepSeek API Key

- 复用 `store/secrets.ts` 的 AES-256-GCM，新增通用 `saveSecret(name, value)` / `loadSecret(name)`，落 `data/secrets/keys.enc`（一个信封、多键）；
- 优先级：**环境变量 > 加密保存**（CI/脚本继续可用）；
- 前端只显示「已配置 · 尾号 abcd」，永不回显明文；
- 保存时校验格式（`sk-` 开头、长度），失败返回 400；
- `getDeepSeekKey()` 注入到 adapters 的 `extractStyle` / `analyzeImage`，替换直接读 `process.env`。

### 2.2 Vault 目录

- 现状：`vaultHome()` = env `DESIGN_VAULT_HOME` > workspace root；
- 新增根目录指针文件 `.design-vault-home`（内容为绝对路径，加入 `.gitignore`）；
- 解析优先级：**env > 指针文件 > workspace root**；
- 设置页显示当前路径（只读）与「更换目录」：
  - 服务端校验：绝对路径、存在、可写、不是文件系统根、不是当前仓库的 `node_modules`；
  - 写入指针后提示「需要重启 dev server 生效」（Next 的模块缓存不会热切换 Vault）；
  - 提供「初始化新 Vault」：在目标目录下创建 `data/*.json` 空集合与 `config/upstreams.json`，不覆盖已有文件。
- 注意：切换 Vault 后，`data/secrets` 与 `refs/` 都跟随新目录，设置页要提示这一点。

### 2.3 订阅 UP 主管理

- 直接复用现有 `GET/POST/DELETE /api/upstreams` 与 `readConfig/addUpstream/removeUpstream`；
- `/settings` 内嵌一张表：UID、昵称、上次检查、移除；顶部输入 UID + 添加（服务端查昵称，失败友好报错）；
- 与 `/subscriptions` 的表格共用同一个客户端组件，避免两套逻辑。

### 2.4 设置页结构

```
/settings
├─ B 站账号（已有）
├─ API 密钥（DeepSeek，加密）
├─ Vault 目录（当前路径 / 更换 / 初始化）
├─ 订阅 UP 主（增删）
└─ 危险区：清空登录态、清空加密密钥
```

## 5. 需要你拍板的三件事

1. **批量提取的上限**：我建议一次最多 20 条、串行、每条 1–3s；如果你希望整夹全抓，需要加「后台任务 + 进度页」，成本更高。
2. **Vault 切换的生效方式**：我建议写指针文件 + 提示重启（最稳）；如果你要「保存即生效」，得给 Next 加运行时重载逻辑，风险高。
3. **收藏夹范围**：只读「我创建的收藏夹」，还是也读「我收藏的（别人创建的）」？后者接口不同（`/x/v3/fav/folder/collected/list`），建议 V2.1 先只做自建。

确认这三点后，我按 M7a → M7b → M7c 开工，每阶段一个 commit 并跑全量测试。
