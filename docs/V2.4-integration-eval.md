# V2.4 评估：插件与 WebUI 一体化（A/B/C 三方案）

> 结论先行：**短期做 C（一键启动），中期做 A 的分阶段版本；B 只作为过渡桥，不建议终态。**
> 本文基于 DSH 官方文档与现有插件源码的实际能力，不是猜测。

## 1. 我在 DSH 侧确认到的能力

依据：

- 官方 Slots 文档：<https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/slots.md>
- 本项目插件的实际用法：`src/client/index.tsx` 里已经注册了

- `packages/dsh-plugin/AGENTS.md`：Host half = “services, tools, routes. No browser APIs.”

### 能力矩阵

| 能力 | 结论 | 依据 |
| --- | --- | --- |
| 客户端渲染复杂 React 页面 | ✅ 已成立 | 插件已经在 `main` 槽位渲染双栏工作台（表单 + 画布 + 导出） |
| 客户端自定义 CSS / 字体 / 交互 | ✅ | 单文件 scoped CSS，`main` 整页渲染 |
| 客户端发起 fetch / 调宿主服务 | ✅ 理论成立，**需一次 spike 验证** | Slot 文档：`inject` 工厂可闭包注入 Cordis 服务；框架提供 `useRemoteAccess`（global Remote） |
| 宿主读写文件（Vault） | ✅ 已成立 | `src/host/vault-reader.ts` 已直接读 `data/styles.json` |
| 宿主注册 HTTP 路由 | ⚠️ 文档提到 host 有 “routes”，但具体 API 未在公开页确认 | 需 spike：找 `ctx.server` / `ctx.router` / `webserver` 服务 |
| 宿主 spawn 子进程（起 Next） | ⚠️ 未确认 | Electron 主进程通常可以，但插件是否有 `child_process` 权限需实测 |

结论：**A 的前半（渲染）已经具备，卡点在“客户端 ↔ 宿主”的数据桥**；B 卡在进程管理与 CSP。

## 2. 三方案评估

### 方案 A：把页面收进插件（终态）

**可行性**：架构上成立。插件已经能占满 `main` 槽位；宿主是 Node，能直接复用 `packages/core / store / adapters`（我们 Monorepo 的成果正好在这里变现）。

**代价**：

- 四个页面（pending / settings / search / components）目前是 Next Server Components，要改写成客户端组件 + 通过宿主服务取数；
- B 站抓取、DeepSeek、Playwright 截图、ffmpeg 截帧这些**重服务**要搬进宿主：Playwright/sharp/ffmpeg 的原生依赖会让插件包变大，且 DSH 宿主是否允许这些依赖需验证；
- 两套 UI（Next + 插件）会分叉，需要组件共享策略。

**工作量**：大（约 2–3 周）；**UX**：最好；**风险**：数据桥未验证。

### 方案 B：插件宿主托管 Web

**可行性**：宿主若能 spawn 进程，可以 `next start`（或 standalone）起 3000，再让插件用 iframe / 浏览器打开。

**代价**：进程生命周期（DSH 退出、崩溃重启）、端口占用、打包 Next 产物、CSP/iframe 白名单；比 C 只多一层“自动拉起”，但把不确定性放进了插件里。

**结论**：只适合作为 A 的过渡（插件里放一个“打开完整工作台”按钮），不适合终态。

### 方案 C：一键脚本（最稳）

**可行性**：100%。写 `launch.mts` + `start.bat` / `start.sh`：

1. 检查 Node / pnpm（没有就提示 `corepack`）；
2. 安装依赖（首次）；
3. 构建插件（可选）；
4. 后台启动 `apps/web`，等 `/api/health` 就绪；
5. 打印地址、自动开浏览器、写 PID 与日志；
6. 提供 `stop` 参数。

**代价**：1 天；**UX**：仍需 DSH 装插件 + 双击脚本；**风险**：最低。

## 3. 推荐路线

```
现在：C（一键启动）—— 先让同学能用
之后：A 的 spike（1 天）—— 验证 host route / Remote / fetch
若 spike 通过：A-lite（只读库 + 审核 + 设置），抓取仍留 Web 或逐步搬
长期：A 全量，Web 退化为开发/调试入口
```

### 为什么不是“直接上 A”

A 的 UI 壳已经就绪，但数据桥（客户端怎么拿到宿主读到的 JSON、怎么写回）没有公开文档可查；如果先重写四个页面再发现桥不通，返工成本极高。**先花一天做 spike，再决定是否投入 2–3 周**，这是最稳的顺序。

## 4. 若做 A，`apps/dsh-plugin` 的结构改造

```
apps/dsh-plugin/src/
├─ host/
│  ├─ index.ts              # apply(ctx)：注册服务 / 路由 / 工具
│  ├─ services/vault.ts     # 包装 @design-vault/store + adapters（读写 data/*.json）
│  ├─ services/session.ts   # getBiliCookie / 扫码状态（复用 adapters/auth）
│  ├─ routes/               # 若 ctx 支持 HTTP：/plugins/design-vault/*
│  └─ tools/                # agent 工具：list_pending / approve / merge / search
├─ client/
│  ├─ index.tsx             # 只做 slot 注册与路由（列表/详情/设置）
│  ├─ api.ts                # 统一客户端调用层（Remote 或 same-origin fetch）
│  ├─ pages/
│  │  ├─ LibraryPage.tsx
│  │  ├─ PendingPage.tsx
│  │  ├─ ComponentsPage.tsx
│  │  └─ SettingsPage.tsx
│  └─ ui/                   # 共享的 NASA-Punk 组件（从 web 抽出）
└─ shared/                  # 继续 re-export @design-vault/core
```

关键改动：

1. `client/api.ts` 成为唯一数据入口（现在是静态数据，未来换成宿主调用）；
2. 页面从 Next Server Component 改成客户端组件，`params/searchParams` 换成 props/state；
3. 写操作（审核、合并、设置）全部走宿主服务，保证与 Web 端同一套 store 逻辑；
4. 重服务（Playwright/ffmpeg）先留在 Web，插件端只做「读 + 审核 + 设置 + 搜索触发」，避免原生依赖进插件。

## 5. Spike 清单（1 天，决定 A 是否可行）

1. 宿主里能否拿到 HTTP 路由/webserver 服务并注册 `/plugins/design-vault/ping`；
2. 客户端 `inject` 工厂能否调用宿主服务（或 same-origin fetch 到 `/plugins/.../ping`）；
3. 返回 JSON 的往返是否稳定（大列表 500 条）；
4. iframe 到 `http://127.0.0.1:3000` 是否被 CSP 拦截（决定 B 的可行性）；
5. 插件包内引入 `sharp`/`playwright` 的体积与安装行为（决定抓取是否值得搬）。

任何一项失败，A 全量就不划算，退回 A-lite + C。

## 7. M10b Spike 结果（已执行）

### 7.1 宿主路由 API：确认存在

官方 HTTP Server 文档（<https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/web-server.md>）明确：

- `ctx.webServer.register({ kind: "exact" | "prefix", path, handler })` 注册命名路由，返回 disposer；
- `ctx.connection.requestRejection()` 提供 Host/Origin 与浏览器会话鉴权；
- `ctx.webApi` / shared `/api` 通道由 Connection 挂载，插件通常不需要自己起端口。

结论：**A 方案的数据桥不需要外部端口，插件宿主可以直接挂在 DSH 自己的 HTTP 服务上。**

### 7.2 已实现的 spike 路由

- 文件：`apps/dsh-plugin/src/host/ping.ts`
- 路由：`GET /plugins/design-vault/ping`（支持 `?n=500` 生成测试负载）
- 注册：`src/host/index.ts` 的 `apply(ctx)` 中通过 `ctx.webServer.register` 挂载，disposer 交给 `ctx.effect`；
- 返回：`{ ok, plugin, vault, styles, n, items[], at }`，读取真实 vault 条数。

### 7.3 处理器实测（本地 http harness）

| n | 状态 | 响应体 | 耗时 |
| --- | --- | --- | --- |
| 1 | 200 | 187 B | 14 ms |
| 500 | 200 | 31,410 B | 5 ms |

500 条 JSON 往返无压力；不需要分页或压缩优化。

### 7.4 运行中的 DSH 尚未加载新路由

构建后请求 `http://127.0.0.1:14301/plugins/design-vault/ping` 返回 **404**：当前 DSH 进程加载的是旧的插件产物，宿主代码变更需要 **重启 DSH（或重新加载插件）** 后才会注册。根路径返回 401（DSH 的浏览器会话鉴权），说明路由确实经过 DSH 的 Web 服务。

### 7.5 CSP / iframe

根页面 401，拿不到 index 的 CSP 头/元标签，**iframe 可行性仍未验证**；需要登录后的页面才能判断 `frame-src`。因此 B 方案依旧不推荐作为终态。

### 7.6 依赖体积

插件 client bundle：**306.98 kB（gzip 71.52 kB）**，仅 React 运行时 + 业务代码；没有 `sharp` / `playwright` / ffmpeg。说明「A-lite 只做读/审核/设置、抓取留 Web」在体积上完全可行。

### 7.7 下一步验证（需要你配合）

1. 重启 DSH（或重新加载插件），然后浏览器打开：
   `http://127.0.0.1:14301/plugins/design-vault/ping?n=500`
2. 若返回 200 JSON，说明宿主路由 + 鉴权链路通；
3. 在 DSH 页面 DevTools Console 执行
   `fetch('/plugins/design-vault/ping').then(r=>r.json()).then(console.log)`
   验证客户端同源调用（带会话 Cookie）；
4. 登录后的页面里检查 `document.querySelector('meta[http-equiv="Content-Security-Policy"]')`，确认 iframe 是否可用。

## 8. 桌面端替代方案：本地 HTTP 互调（已实现）

桌面版没有 `ctx.webServer`，因此放弃「插件宿主挂路由」，改为插件 Client 直接请求本机 Web：

- Web 新增 `GET /api/vault/styles-lite`：只返回 `id / name / project_tags / palette / frontend_prompt`，`no-store`；
- CORS：只放行 `localhost` / `127.0.0.1`（任意端口），其他来源不发 `Access-Control-Allow-Origin`；支持 OPTIONS 与 `Access-Control-Allow-Private-Network`；
- 插件加载时 `fetch("http://localhost:3000/api/vault/styles-lite")`，3.5s 超时；
- 失败降级：使用打包的静态快照，并在侧栏显示「未连接到 Web 服务，当前为静态快照」；
- 连接成功后，侧栏出现「静态快照 / 远程风格」下拉，选中远程风格会用它自己的 palette 渲染预览。

### 风险与边界

1. **安全**：只允许本机来源；不要用 `*`，否则任意网站都能读你的 vault 数据。
2. **端口**：默认 3000，可通过 `localStorage.dvp.webBase` 覆盖（插件里暂未做 UI）。
3. **依赖**：必须先启动 Web（start.bat）；否则降级为静态快照，功能不崩但读不到新风格。
4. **CSP 未知**：DSH 桌面渲染进程若是自定义 scheme，可能禁止 `connect-src http://localhost:3000`；第一次加载若直接显示 fallback，就是被 CSP 拦了，需要改走 host 代理。
5. **与插件规范冲突**：`apps/dsh-plugin/AGENTS.md` 写明「No network calls」。本次是用户明确要求的例外，若长期保留，需要更新该规范或把请求收敛到一个可关闭的 gateway。
