## 1. 数据结构

### 1.1 `ComponentSchema`（`packages/core/src/schema.ts`）

```ts
export const COMPONENT_CATEGORIES = [
  "navigation", "hero", "card", "form", "button",
  "table", "feedback", "overlay", "layout", "animation", "other",
] as const;

export const componentSchema = z.object({
  id: slugSchema,
  name: z.string().min(1),
  category: z.enum(COMPONENT_CATEGORIES),
  description: z.string().min(1),
  framework: z.enum(["react", "html"]).default("react"),
  /** 组件源码；允许空串，表示「已登记、待补代码」 */
  code: z.string().default(""),
  dependencies: z.array(z.string()).default([]),
  states: z.array(z.object({ name: z.string(), description: z.string() })).default([]),
  related_styles: z.array(z.string()).default([]),
  related_effects: z.array(z.string()).default([]),
  sources: styleSourcesSchema,
  notes: z.string().default(""),
  confidence: z.number().min(0).max(1),
  created_at: z.string(),
  updated_at: z.string(),
}).strict();
```

## 2. LLM 侧：`item_type` 识别

`adapters/ingest/deepseek.ts`：

1. 系统提示词新增判定规则：

   - `style`：描述的是整体视觉语言（配色、排版、质感），没有具体 DOM；
   - `effect`：描述的是一个具体动效/技术方案（GSAP 滚动、滤镜、粒子），可脱离页面复用；
   - `component`：描述的是**一个可复用的 UI 部件**（带结构、状态、交互），如工牌、卡片、导航、表单。

2. 输出 JSON 增加：

```json
{
  "item_type": "component",
  "component_candidate": {
    "name": "Hanging Pass Identity",
    "category": "card",
    "description": "可拖拽、带挂绳摆动的个人介绍工牌",
    "framework": "react",
    "code": "…可选…",
    "dependencies": ["framer-motion"],
    "states": [{ "name": "dragging", "description": "拖拽时轻微倾斜" }]
  }
}
```

3. `mapPayload` 解析并校验；`pipeline` / `search/extract` 把 `item_type`、`component_candidate`、`effect_candidate` 写进 pending；
4. 提示词遵守既有约束：不编造不存在的依赖/状态，没有代码就返回空串。

## 3. 审核分流

### 3.1 接口

`POST /api/pending/[id]/approve` 接受 body：

```json
{ "as": "component" }   // 缺省 = pending.item_type
```

- `as=style`：现有逻辑（含 extracted_effects 双向绑定）；
- `as=effect`：从 `effect_candidate`（缺省时退回 `extracted_effects[0]`）生成 effect 写入 `effects.json`，`related_styles: []`；
- `as=component`：从 `component_candidate`（缺省时用 name/description 兜底）生成 component 写入 `components.json`，`code` 可为空但 `notes` 注明「待补代码」。

三者成功后都从 pending 删除；`as` 与 `item_type` 不一致时以人工选择为准（允许纠正误判）。

### 3.2 `/pending` UI

每条卡片：

```
[组件]  form. — Hanging Pass Identity        CONF 0.7
        来源：bilibili-search · BV…
        [存入风格库] [存入动效库] [存入组件库] [去调色] [丢弃]
```

- 徽标显示 AI 判定的 `item_type`；
- 三个入库按钮即人工纠正入口；
- 组件/动效条目隐藏「去调色」（调色器只对 Style 有意义）。
